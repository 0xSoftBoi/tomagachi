# What we keep

Three files can be written while the shop is serving. This is all of them,
what is in them, how long they last, who can read them, and how to make them
stop. Where a claim here could be false, there is a test holding it true —
`agent/test/retention.test.ts` and `agent/test/zdr.test.ts`.

## The revenue ledger — `state/usage.jsonl`

One line per completion. A line is exactly these fields and no others:

```
at  character  app  promptTokens  completionTokens  revenueUsd  gpuSeconds  costUsd  latencyMs
```

**No prompt, no completion, no session key, and no customer identifier.**
`record()` builds the row field by field from that list rather than spreading
what it was handed, so a future refactor that starts passing messages through
finds them dropped instead of persisted. A test asserts the key set of a
written row and tries to smuggle a conversation in through the argument.

`app` is the one field a stranger controls: it comes from `HTTP-Referer` /
`X-Title`, which routers pass through from whatever the app set, and a referer
is a URL. `sanitizeApp` keeps the origin and path and drops the query, the
fragment, and any embedded credentials, then runs the same redaction capture
uses. `https://janitorai.com/chats/9f2?email=kit@example.com` is stored as
`janitorai.com/chats/9f2`. That keeps concentration risk measurable — which
logos carry the volume — without keeping the person.

**Retention: indefinite.** This is the business's own accounting record, and
it holds no personal data to expire. `/metrics` reads only the last
`HISTORY_DAYS` (28) into memory; the file keeps everything.

**Readable by:** the operator, on the box. `/metrics` serves aggregates
publicly and by design — the creature's P&L is meant to be public — and
publishes no per-request rows.

## Session memory — `state/sessions.json`

Up to 12 short facts per session, extracted by pattern from what the customer
typed: their name, what they like, where they work. This is customer text. It
is the thing the price premium is sold on and the most sensitive thing here.

- **Keyed** by `sha256(caller principal ‖ their session id)`, so the file holds
  neither the id they chose nor the token they sent, and one caller cannot read
  another's facts by guessing an id (`agent/SECURITY.md`).
- **Retention: 7 days** from the last turn, with a hard cap of
  `MEMORY_MAX_SESSIONS` (5000) evicted oldest-first. Both are enforced on every
  write, not only at startup.
- **Deletion: `DELETE /v1/sessions`**, with the same `X-Suwa-Session` header
  (or `?user=`) sent to chat. The key is derived from the caller's own
  principal, so this erases your memory and cannot erase anyone else's. No
  ticket, no operator, no waiting. Verified live: a second caller sending the
  same session id gets `{"deleted":false}`.
- **Off entirely** under `ZERO_DATA_RETENTION=1`.

## Captured transcripts — `model/data/captured/*.jsonl`

Off unless `CAPTURE_TRANSCRIPTS=1`, refusable per request with
`X-Suwa-No-Capture: 1`, redacted before write, and never mixed into the
curated training set. `agent/src/capture.ts` documents the rest. Redaction is
best-effort pattern matching and is not anonymisation — which is the honest
reason the manifest cannot claim ZDR while capture is on.

**Off entirely** under `ZERO_DATA_RETENTION=1`, including when
`CAPTURE_TRANSCRIPTS=1` is left set from an earlier deployment. The stronger
claim wins; a test tries exactly that combination.

## The ZDR switch

`ZERO_DATA_RETENTION=1` turns off session memory and transcript capture. The
ledger keeps running, because it holds counts and no text.

There used to be a `COMPLIANCE_ZDR` flag that changed only what the manifest
said. A flag that changes the advertisement and not the behaviour is worse
than no flag: it is a false statement to a router, made one environment
variable at a time. It is gone. `compliance.zdr` in `/provider/models` now
reads the switch that does the disabling, so the claim cannot be made without
the behaviour behind it.

Verified live with the switch on: two turns naming a person and a town, and
afterwards `state/` contained `usage.jsonl` and nothing else, the capture
directory was never created, the second turn reached the model with no memory
block, `/metrics` reported zero sessions held, and `/provider/models` reported
`zdr: true` for every SKU.

## What we do not control

The completion is generated by vLLM on the GPU box, and the request passes
through whatever router sent it. This document covers what this process writes
down. A router's own retention is the router's to declare, and a self-hosted
vLLM keeps its logs where its operator points them — `deploy/README.md`
covers turning request logging off there.
